# Design harmony audit — D'Royal Village

Date: 18 September 2026. Baseline: `DESIGN.md`, `antislop.md`, and `antislop-ui`.

## Verdict

The brand is recognizable, but the interface is not yet consistent enough to pass the documented design gate. Shared controls, mobile table composition, and keyboard access deserve attention before decorative refinements. Keep the logo, Outfit/Geist roles, quiet green/ivory surfaces, active-column sort arrows, and operational terminology. A replacement theme or new UI library is unnecessary.

This is an audit, not an implementation. No business records or application code were changed. Theme was returned to light and temporary mobile viewport override was removed.

## Evidence and coverage

Browser inspected as the authenticated administrator on localhost:

- Dashboard; Material; Alat; Gudang; Supplier; Kategori; Rumah; Cluster.
- Transaksi Material & Alat; Catatan Material; Catatan Alat; Biaya Rumah; Manajemen User.
- Profile, password, and appearance settings.
- House detail `2026-A01` visually inspected.
- Material filter and import dialogs opened without submitting.
- Material page inspected at 390 × 844; material history sampled in dark mode.

All 16 main pages loaded without an error screen and without document-level horizontal overflow at the sampled desktop viewport. This does not prove every action or state works. Source review covered shared CSS, navigation, table headers, modal markup, and page templates. Warehouse detail was navigated to, but its screenshot was not retained as usable audit evidence.

Not fully exercised: every detail page, every dialog, authentication/2FA screens, non-admin roles, all breakpoints and dark-mode combinations, validation/request-failure states, export layouts, and print output. No destructive or record-changing workflow was tested. This report is a broad design audit with explicit coverage limits, not certification of every element.

## Prioritized findings

### 1. High — primary and financial colors miss contrast requirements

Evidence: shared `.btn-success` uses white on `#1F9B3A` (`resources/css/app.css:51`). Calculated contrast is **3.62:1**, below the 4.5:1 requirement for normal text. Lime `#78C800` on white is **2.09:1**, below even the large-text 3:1 threshold; the house-detail financial total visibly uses this treatment. These ratios concern the specified solid color pairs, not a claim that every gradient/status pairing was measured.

Fix: keep brand green as an identity accent, but assign a darker action/text token. Existing forest `#136928` gives white text **6.82:1**. Use dark ink for financial amounts and reserve lime for supporting non-text emphasis. Check hover, disabled, status, focus, and dark-mode pairs separately. Update DESIGN.md with the accessible action token rather than silently contradicting it. Rules: R-25, R-29.

### 2. High — filter dialog does not follow the keyboard contract

Browser confirmed: opening Material's filter leaves focus on the underlying Filter button. Escape leaves the dialog open. Its `role="dialog"` has no accessible name. Source: `resources/views/components/filter-modal.blade.php:38` and `:42`.

Fix: connect the title with `aria-labelledby`, move and contain focus, support Escape, and restore focus to the opener on close. Audit the other modal implementations against the same contract. Do not assume that adding `aria-modal` implements keyboard behavior. Rules: R-32 and DESIGN.md dialogs.

### 3. High — touch controls are smaller than the project's 44px minimum

Browser measurements include Filter 38px, inventory Import/Export 39px, primary add action 43px, settings Save 42px, and some desktop row actions 24–32px. The mobile Material screenshot confirms compact Import/Export and Filter controls remain. Source: `filter-modal.blade.php:8`, `:26`; `app.css:1164` and `:1203`.

Fix: standardize interactive hit areas to at least 44px on touch layouts, including icon buttons and pagination. Keep visual icons small if desired; enlarge the actual target. Desktop density can remain compact when it does not undermine keyboard focus or touch use. Rule: R-03.

### 4. High — appearance selector is not a keyboard control

Theme options are clickable `div` cards without button/radio semantics or keyboard handlers (`resources/views/livewire/settings/appearance.blade.php:28–50`). Browser accessibility snapshot exposes headings and generic text, not theme controls. Mouse switching works.

Fix: use native buttons with selected state, or a labelled radio group. Preserve the existing visual theme choice; add keyboard activation and visible focus. Rule: R-32.

### 5. Medium — mobile inventory starts with metadata instead of usable item identity

Browser confirmed at 390px: table region is 320px wide, while the name column is fixed at 256px. Initial table view shows No., Foto, and Kode before a clipped name. The fixed name width will consume most of the viewport as horizontal scrolling advances. Source: `resources/css/app.css:841–844`, sticky rules around `:938–972`.

Fix: make name/code the first mobile identity field, combine or suppress low-priority metadata, and use a smaller responsive identity width. Preserve access to all quantities, warehouses, and costs through deliberate horizontal scrolling or a detail view. Do not squeeze all 12 columns into tiny text. Rule: R-03 and DESIGN.md table guidance.

### 6. Medium — page hierarchy changes between modules

Measured desktop headings are approximately 48px on most list pages versus 28px on Transaksi. Settings has no h1 and starts with an h2. On mobile Material, the header plus two large summary cards fills the first viewport before search or stock rows appear. Sources: `materials.blade.php:8`, `warehouses.blade.php:7`, `clusters.blade.php:7`, and transaction/settings templates.

Fix: choose one operational page-heading scale, a predictable title/actions row, and a compact summary treatment. Keep Transaksi's form-first composition intentional, not identical to a list page. On inventory mobile layouts, place search/data sooner. A 28–32px desktop heading is a candidate to validate, not an arbitrary mandate. Rules: R-05, C-3; RHYTHM 1.

### 7. Medium — primary-action styling is inconsistent

Browser confirmed Material import's `Proses & Validasi Import` is Bootstrap blue (`rgb(13,110,253)`), while page actions are green. Source: `materials.blade.php:741`; equivalent import templates also use `btn-primary`. Main action heights range from 38px to 62px; Export Excel wraps on history pages. Different sizes may be legitimate, but the current variation does not communicate a stable hierarchy.

Fix: one accessible primary treatment, one secondary outline treatment, and explicit size variants. Give title/action rows enough space or wrap the action group deliberately; avoid accidental two-line button labels. Reuse existing components/classes before adding abstractions. Rules: R-01, R-29, R-31.

### 8. Medium — empty-state copy confuses an empty system with no search matches

Source: warehouse and cluster `@empty` branches say to add the first record, regardless of whether filters/search caused the empty result (`warehouses.blade.php:63–65`, `clusters.blade.php:64–66`). Material uses generic “Belum ada data material” at `materials.blade.php:213–215`. State coverage is uneven across modules.

Fix: distinguish first use from filtered-empty results. For filtered results, explain no match and offer reset; for a genuinely empty dataset, offer creation only if permitted. Standardize pending and request-failure feedback as a separate verification pass. Rule: R-27. Filtered-empty behavior was source-reviewed, not exhaustively browser-tested.

### 9. Medium — blanket truncation threatens operational readability

Source: broad table rules force nowrap/ellipsis, including `.log-wrap` (`resources/css/app.css:848–887`). This is useful for identity columns but risky for work descriptions and notes.

Fix: classify columns deliberately: numbers stay on one line, short identities may truncate with an accessible detail path, and important notes can wrap or expand. Check keyboard and touch access to full values; a hover-only title is not an adequate mobile solution. This is a source-identified risk, not a claim that every current row loses information.

### 10. Medium — surface layering competes with the working data

Browser screenshots show outer shell, large header card, summary cards, filter card, and table container, often all rounded/elevated. House detail has the same stacked surface language. Shared CSS has multiple blur layers (`app.css:299`, `:330`, `:370`).

Fix: retain intentional shell/sidebar transparency, but flatten ordinary grouping inside the workspace. Use borders and spacing for lists and summaries; reserve elevation for overlays. Apply the documented shell/group/control radius hierarchy instead of adding more decorative effects. Not every card is wrong: keep cards that contain a distinct task. Rules: R-10, R-11, R-12.

### 11. Low — localization and terminology are incomplete

Browser confirmed English pagination (“Showing…results”, “Previous”, “Next”) inside Indonesian pages, and “Account Settings” on settings. Import/Export naming also varies from longer Excel labels.

Fix: localize shared pagination and settings headings, then establish a small glossary for Import/Impor, Export/Ekspor, User/Pengguna, Supplier/Pemasok. Preserve terms familiar to staff rather than changing vocabulary solely for aesthetics. DESIGN.md language requirement.

### 12. Low — reduced-motion coverage is incomplete

Source: the reduced-motion block at `resources/css/app.css:994` targets selected sidebar/row-action transitions, while later hero-action transitions are separate (`:1164–1226`).

Fix: cover all custom animated interaction classes under reduced motion and verify the resulting experience. Do not remove useful instantaneous state feedback. This was source-reviewed, not tested with an OS motion preference override. Rule: R-19.

## Keep what already works

- Real, task-specific navigation and recognizable D'Royal Village branding.
- Shared sortable headers: active-only arrow, descriptive accessible labels, and sort state.
- Numeric alignment and tabular/monospaced operational values.
- Intentional table scroll regions instead of document-level desktop overflow.
- Approximately 56px standard inventory rows; content may legitimately need taller rows.
- Responsive sidebar replacement and an existing dark-theme implementation.
- Wide-table striping where it helps track a long record; do not remove it indiscriminately.

## Implementation order

1. **Shared accessibility:** contrast tokens, button hit areas, filter-dialog keyboard behavior, native theme controls.
2. **Shared composition:** page heading/action layout, compact mobile summaries, surface and radius hierarchy.
3. **Tables:** mobile identity columns, readable notes, pagination localization, consistent state messages.
4. **Verification:** remaining detail/auth/security pages, each supported role, light/dark, mobile/desktop, keyboard, validation, loading and failure states.

Acceptance before calling the system harmonious: normal text >=4.5:1; large text >=3:1; touch targets >=44px per project rules; dialogs named and keyboard-operable; no document overflow; full record values accessible without hover; primary actions visually consistent; no business logic or stock totals changed by presentation work.

The antislop-ui guidance shaped this audit toward functional hierarchy and shared fixes, not a new theme, decorative animation, or a wholesale redesign.

## Renovation pass completed

The first shared-layer pass applied the following:

- Accessible forest action token for primary/success controls, including import actions; white-on-action contrast is 6.82:1.
- Dark gold warning/financial text token replaces low-contrast lime text for totals and attention labels.
- 44px mobile hit areas for ordinary buttons, close controls, filter controls, hero actions, and import modal actions.
- Mobile inventory tables hide secondary No./Foto columns so Code and Name are visible at the starting scroll position.
- Filter dialog name, initial focus, Escape close, focus cycling, and opener-focus restoration.
- Theme choices converted from clickable generic containers to keyboard-operable controls with pressed state.
- Consistent list heading scale and broader reduced-motion coverage.

Verification after the pass:

- `npm run build` passed with Vite.
- `php artisan view:cache` passed.
- `git diff --check` passed for the changed source files.
- Browser checked Material desktop, Material mobile at 390 × 844, filter dialog, import modal, appearance settings, and both theme modes. The browser was restored to light mode and the viewport override was removed.

The remaining medium/low findings are intentionally left for a second pass: localized pagination, filtered-empty copy, long-value disclosure, surface flattening, and deeper detail/auth/role-state coverage.
